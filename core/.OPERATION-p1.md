## Notes
- Watcher/discovery now covers startup scanning, path-only model detection, markdown validation, provisional sync-action decisioning, debounced filesystem events, and self-write suppression.
- Reconciliation execution now applies supported create, update, rewrite, and purge flows, including canonical markdown sync-back for discovered file changes.
- Objective markdown storage is now treated as synced, including directive-contained objective files and standalone files under the `Objectives` root.
- A new sibling CLI package now exists under `../cli`, and its first milestone is complete: a modular command engine with DI activation, typed option binding, help generation, and grouped subcommand support. Its current concrete commands still forward into the core entrypoint while the true API-client surface is built out.
- Onrush and Polaris API surfaces now use the shorter `/api/onrush/*` and `/api/polaris/*` route groups.
- Operational state rules are now partially centralized through EF Core save hooks: active onrush/polaris exclusivity, terminal-objective Celestron settlement, and superseded forecast cleanup are enforced from a reusable state-policy processor instead of being hand-coded only in individual endpoints.
- PEP091 implemented: PUCK identity storage form (`Quiet`/`Index`) is now decoupled from storage mode via `VaultStorageAttribute.PuckStorage`, and a new `Implicit` storage mode with `BoundaryBegin`-gated synchronization boundaries was added. `Objective` is the first implicit entity (quiet frontmatter identity, on-demand file materialization via `POST /api/objectives/{id}/begin`, boundary-authoritative deletion). The `AuditLogEntry.Action` column is indexed for boundary checks.
- PEP092 implemented: a vault migration system (`Pleiades.Vault.Migration`) now runs alongside the database migration during vault initialisation. The vault stores a `SchemaVersion` in `.plaintorch`; `VaultMigrationRunner` upgrades on-disk conventions by loading the vault under the stored version's `VaultConventionSet` and re-canonicalising each entity under current conventions (body-preserving, graveyard-backed rollback, idempotent, recorded in `VaultMigrationHistory`). The first migration (v1→v2) backfills pre-PEP091 objective files into the quiet form. This is also the first abstraction of the vault↔database boundary.
- PEP093 implemented: the core now has an automated test suite (`../core.tests`, xUnit) driving the real DI graph over a fresh isolated vault per test (`TestVault` harness). A dev-latch environment was added to `serve`: `--ephemeral` (random user-independent temp profile for tests/sandbox), socket-only by default with opt-in `--loopback`, and interactive relaunch as the static `PLAINTORCHDEV` account (setup scripts under `DevUser/`). Coverage/invariants are catalogued in `_documents/Criteria - Validators, Checks & Unit Test.md`. This begins addressing the observability/test-coverage gap ahead of the planned dispatch-coupling refactors.
- PEP100 orbit refinements (core + SDK): resolution calendars are now modular — decree orbits (attentives) and reflective day-matching resolve on the new `OrbitPleiadeanCalendar` (six 61-day months, Persian-leap-coupled) by default, while fate orbits (eventives) stay Gregorian. Decree orbits accept any granularity: sub-day occurrences produce timed attentives, and super-day occurrences record `Attentive.PeriodEndDate` so one instance's period collides with multiple Polaris cycles (inclusion queries are period-aware); only reflective schedules remain strictly day-granular. Span-format fate orbits (`=<dur>`) are now accepted and fill the eventive's start/end/length directly, so orbit-based fates need no duration override. Seeking now catches up from the persisted state (everything pending up to the window end resolves exactly once, keyed by occurrence date+time). `Decree.AttentiveReward` was renamed to `ActiveCelestron` (entity, column, contracts, SDK).
- PEP100 orbit wave (core + SDK): the Orbit Scheduler engine is now ported to C# as `Pleiades.Orbits` (statement-faithful to `@pleiades/orbits`; fidelity-verified against the TypeScript reference including seeded randoms and cross-language snapshot handoffs) with a day-granularity facade. Declaratives gained objective-style vault policies (`Implicit`, quiet PUCK, `Fates/`/`Decrees/` roots + directive partitions, begin-boundary endpoints, full watcher registration). Orbit notations validate at set-time to day granularity; per-declarative engine state lives in `OrbitScheduleStates`, reset on orbit change and advanced only by seeking resolution. Cycle begin now seeks orbit fates→eventives and orbit decrees→unbound attentives through the 24h window, while lunar reflect-decrees day-match the cycle's start day and generate cycle-bound reflectives (`Reflective.DecreeId` provenance). Interaction validates orbit occurrences in preview (non-seeking) mode; occurrence dates are instance identities so future instances aren't re-resolved.
- PEP100 implemented (core + SDK): the declarative ecosystem. `LunarDirective` joins `Directive` as a TPH sibling (`LUNA{S:3}`, moonlight states OnHold/Active/Stale); the `Objectives` table became `Incentives`, hosting `Objective`/`Fate`/`Decree` under the new abstract `Incentive` base (`e{S:8}`/`r{S:8}`) with the PEP100 parent system (objective→objective/fate, fate→fate, decrees exempt). New executive-shaped backlog records: `Attentive` (decree occurrences; bound via manual add-to-cycle, unbound via interaction/proximity; done/skipped, reschedule-vs-move mobility rules) and `Eventive` (fate/objective-due occurrences; never bound; movable; missed/cancelled). Proximity materialization runs at Polaris begin for the 24h window, and `/api/polaris/*/inclusions` serves the non-structural inclusion list. Rewards run through the state policy processor: decree-predefined per-execution attentive rewards and the fixed all-reflectives-done collection reward. Timeframes hang off directives with executives naming one as semantic affinity. Full API surface (`/api/fates`, `/api/decrees`, `/api/eventives`, `/api/attentives`, `/api/directives/lunar`, timeframes) with SDK mirrors (`client.declaratives`, lunar/timeframe methods, inclusions). JSON payloads for directives/incentives are polymorphic via `$type`. Orbit strings are stored but not yet evaluated — the Orbit syntax spec is still pending, so orbit-driven proximity and timeframe cycle-scoping await it.
- PEP099 implemented (core + SDK): a new `ExecutiveOrder` orchestration entity attaches constraints/directions to an owning `OnrushSprint` (`Title`, optional `Summary`, `EffectiveFrom`, `EffectiveUntil`). Identity uses the composite declaration `x{?}-o{I:2:1}` where the manual segment carries the owning onrush's trimmed numeric part, and incremental PUCK sequences are now prefix-scoped so each onrush numbers its own orders (`x180-o01`, `x180-o02`; `x181-o01`). Storage is `Synced`/single-file/`Index` under the sprint's `ExecutiveOrders` partition folder, with full watcher participation (catalog model, path composition, create/update/rewrite/delete reconciliation, and required-parent validation). The API exposes issue/list under `/api/onrush/{id}/orders` and update/delete under `/api/executive-orders/{id}`, mirrored in the TypeScript SDK (`onrush.issueExecutiveOrder`, `listExecutiveOrders`, `updateExecutiveOrder`, `deleteExecutiveOrder`).
- PEP098 implemented (core + SDK): `Executive` now carries three optional whole-minute working-time-unit allocations — `Estimation` (primary, doubles as progress), `Minimum`, and `Maximum` — reconciled by `Executive.NormalizeTimeAllocations()` (a newly-provided bound seeds the estimation when it is still unset, and the estimation is always clamped into `[Minimum, Maximum]`). The allocations are settable at plan time (`PolarisExecutivePlan`) and via `ExecutiveUpdate` (set + `Clear*` flags), persisted through the `ExecutiveTimeAllocations` migration. The TypeScript SDK mirrors the new fields and adds `@pleiades/sdk/helpers` working-time-unit conversions (`workingTimeUnitToHours`, `hoursToWorkingTimeUnit`, `formatWorkingTimeUnit`, `sumWorkingTimeUnits`) for the hours+fraction and clock/timespan translations.
