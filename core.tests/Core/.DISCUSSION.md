
### 16. Dependency system (PEP101)
A directed blocking-edge system now spans stellar directives, objectives, whole fates, fate/objective
occurrences (eventives), and checkpoints (lunar directives excluded). Source-side `Trigger` (OnBegin/OnFinish)
selects what satisfies an edge; target-side `Constraint` (ToBegin/ToFinish) selects the gated transition;
both default (finish-triggered, begin-constraining) and are empty for checkpoint endpoints.

Resolved this pass:
- Begin/finish are declarative (`[LifecyclePhase]`/`[LifecycleStatus]` + `EntityLifecycleResolver`), with an
  `ILifecyclePhaseSource` hook for eventives (temporal passing). Activation validation requires a begin+finish.
- `DependencyReconciler` (inside the state-policy save pass) maintains edge `Satisfied` and checkpoint
  `Unlocked` to a fixpoint; `DependencyGateService` rejects gated status shifts and freezes locked-fate
  materialization. The lock is emitted separately from `status`.
- Eventive references are CalDAV-shaped (owner `UID` + original-slot `RECURRENCE-ID`), backed by the new
  stable `Eventive.RecurrenceId` so a reference survives a move.
- Checkpoints (PUCK `cc{S:6}`, DB-only) unlock on deps + toll + external condition; the toll is a negative
  `CelestronTransaction`, order-independent, and unlock cascades through checkpoint→checkpoint edges.
